# 訓練工作區

T05 將 T02 的清單審查與資料出口接到 `#/training`。原生平台側欄選「訓練工作區」；資料審查使用 CPU，不載入 trainer 或模型。Docker 不提供 Windows 原圖／訓練操作。

## 圖片與標註審查

1. 先用 [T02 CLI](dataset-contract.md) 建立清單；填入原圖的完整目錄，選擇清單 JSON。有 `parent_study` 的清單還需選擇**原始 bytes 未修改的** R02 study JSON。
2. 按「匯入待審查清單」。介面核對原圖大小、SHA256、尺寸與完整解碼，保留待審查狀態，不自動補 caption、來源依據或角色。
3. 選擇每張圖片，核對預覽及內容標註、畫風觀察、來源用途、審查人與角色身分。畫風與角色沿用不同清單；同作者不是同角色的證據。
4. 輸入新版本名稱並「保存新版本」。SQLite 保留不可變的舊修訂，可下載每個修訂的 T02 JSON；原圖與原清單不會改寫。
5. 「重新檢查原圖與標註」核對已保存版本。未保存編輯不混入檢查或匯出；來源改變後需重驗，前一次通過不是永久有效。
6. 通過資料出口檢查後，明確匯出訓練資料包；只複製 train PNG／caption，validation／test／excluded 不進 trainer 目錄。匯出不開始訓練。

本機已保留的待審查輸入：畫風清單 `runtime/t02-dataset-study-20261023/style-v1.json`、角色清單 `character-v1.json`（同目錄），前序清單 `runtime/r02-reference-study/study-manifest.json`。原圖仍選使用者先前提供的 `artist_ref/ハシスタジオ_pixiv` 完整目錄。這些 runtime 檔案不在 Git，其他電腦須先還原或重新建立，不能只 clone 專案就當成已取得圖片。

保留／排除圖不能透過此介面改作訓練來源，既有曝光紀錄不可移除。最終評估圖不提供預覽與互動編輯，避免資料審查提前曝光；需要最終評估時另循 T04 流程。train 候選只可改作開發評估或排除；最終 test 須在首次匯入前獨立分割，不能把已進入審查的候選改稱未曝光，跨原作分組及 R02 原分割仍由 T02 檢查。角色路徑須逐張確認 target 與唯一 subject ID；未知時保持待審查。修訂衝突拒絕保存，保留目前編輯供人工比較，不合併或覆蓋其他版本。

匯入／匯出使用原 UUID；回應不明時按「查回原匯入資料集」／「查回原匯出結果」，不自動重送。匯出若是 exporting／failed，原輸出保留供檢查，不覆寫或接續；需要新的明確嘗試時重新載入資料集，建立新匯出 UUID。平台在 exporting 階段中斷時，狀態可能持續為 exporting；保留目錄並以 T02 verify-bundle 人工核對，不能當作成功。

## T07 缺項導覽

匯入或載入資料集後，在「圖片與缺項導覽」依圖片 ID、相對檔名或原作群組搜尋，搭配用途／缺項類別篩選。缺項以後端已保存修訂的檢查為準，未保存的 caption／來源編輯不會讓舊缺項消失；先保存並重新檢查。篩選本身不改資料、不自動批准或匯出。

每頁 20 個圖片入口、50 個圖片缺項，完整分頁取代原先只顯示前 200 個問題。資料集層級的問題／提醒獨立顯示，不會因圖片搜尋藏起來。未知缺項代碼仍原樣保留。點「定位圖片」會清除圖片篩選、移到該圖所在頁並聚焦審查欄位；「下一張有阻擋缺項」依原清單順序循環。切換或篩選不丟失同份清單的未保存標註；已選圖不符合篩選時仍保留並提示，空結果也不會宣稱資料通過。

最終 test 可定位其紀錄但仍不提供原圖預覽與欄位編輯。保留／排除用途與曝光規則沿用 T05，導覽不會把 test 變成訓練候選。操作與有限驗收見 [T07 紀錄](../validation/training-review-navigation-20261025.md)。

## 保存與備份

來源目錄、原始 study 文字、每次清單、正規化 hash、修訂及檢查快照存於 SQLite 的 `training_review:*`；匯出 UUID／狀態存於 `training_export:*`。資料包位於 DATA 的 `training_bundles/<UUID>`，由完整 DATA 備份保存。GET 清單／修訂不重讀全部圖片；圖片預覽重新核對該原圖，匯出重驗全部來源。

外部原圖不會因備份 DATA 一併收進來，需要另備份。run、trainer、權重與原始驗收資料仍在 runtime，依 [T03](runtime.md)／[T04](artifacts.md) 分別保存。資料包含絕對路徑，搬移或還原到新位置後，須由原清單及原圖重新匯出；舊 TOML 不代表路徑已遷移。

每組最多 100 修訂、最多 100 組資料；大小／格式沿用 T02。每頁顯示 20 個圖片入口，預覽最多 640px。圖片只能依明確登記的清單 ID／修訂讀取，拒絕連結與來源變更。

## 作者圖片提醒

現有作者資料仍為 10 張 train 候選、6 張開發評估、6 張排除，這不是 20 張已訓練圖片。畫風路徑尚缺標註與來源用途審查，角色路徑另外需要逐張身分確認；工具不代填使用許可。

作者試訓前提醒確認來源用途、caption、角色與姿勢／衣著／背景涵蓋；不足才補相應圖片。最終品質比較前，另需未參與訓練與調參的不同原作評估圖。無 final test 的警告保留，不把出口通過認列為畫風／角色品質通過。

## T06 本機訓練與產物

切到「訓練執行」，使用 Windows 原生平台；T03 獨立環境仍先依 [安裝步驟](runtime.md)準備。網頁可檢查環境，不安裝套件或自動下載權重。

1. 選 T05 已封存資料包，填入用途、名稱、512／1024、rank 4／8／16、單一 NVIDIA 裝置、步數、保存間隔、learning rate 與訓練 seed（0～4294967295）。基底固定 Animagine XL 4.0 Opt，不接受任意路徑、trainer flags 或指令。
2. 按「準備新 run」。原請求 UUID 先保存，背景只檢查環境、資料／基底與完整 hash，建立凍結副本；R02 原 study 文件及 bytes hash 隨來源保存。此時沒有訓練 worker。
3. 查回原請求並「開啟新 run」，檢視不可變設定與來源。準備與開始是不同操作；未知回應不自動重做，重新載入可從已保存請求 UUID 查回。
4. **先完成其他 GPU 工作、停止受管理 ComfyUI 8188 與容器平台**，再按「開始此 run 的訓練」。入口拒絕在線引擎、忙碌租約或另一個啟動控制程序，worker 也重驗；不自動結束其他服務。單一 run 的持久啟動標記避免重複建立 worker。
5. 活躍 run 每 2 秒以 GET 查詢，顯示步數、原狀態、程序／租約釋放、資源來源、最多 64 KiB 日誌及產物 receipt。失敗保留上次資料；查詢不開始或恢復訓練，離開網頁也不停止 worker。
6. 「要求停止」只寫該 run 的要求，在下一個步驟起點生效；等程序及租約均釋放才算完成。只有完整保存點可續訓。
7. 按「準備另一個請求」，選未達總步數的完整 checkpoint，以**新請求及新 run UUID** 準備續訓；保留原資料、環境、完整 optimizer／RNG 與總步數，仍須明確開始。不保證資料順序或逐位元等同不中斷訓練。
8. 完成且資源釋放後，「驗證並安裝 LoRA」沿用 T04 完整校驗及不可覆寫安裝。所有訓練結束後自行恢復 ComfyUI，選定 `http://127.0.0.1:8188`，再「同步模型庫與來源登記」。技術產物及條款未審查標記保留。
9. 基底／LoRA 登記完整後，可建立固定比較方案，封存來源、六份方案及人工模板，**不自動生成**；十二件比較輸出仍需在實驗頁明確執行。品質與獨立保留圖依 T04，不以安裝或建方案認列品質。

既有 CLI run 可輸入 UUID「登記既有 run」，只讀受管理 runtime 的紀錄，不啟動或自動掃描其他 checkout。1024、長時間／多圖訓練及其他 GPU 工作負載仍需 E04 實測，不沿用 512 技術容量數字。

## 中斷與資料位置

SQLite 的 `training_request:*` 保存準備／續訓／比較請求，`training_run_link:*` 保存明確登記的 run，`training_start:*` 保存單次啟動要求。平台在準備中退出後顯示 interrupted，不自動重做；啟動標記已保存但 worker 未確認時顯示 start_unknown，保留原 run／日誌，先核對再明確建立新嘗試。

run 的 manifest／work／parent-study／checkpoint／資源／日誌在 `runtime/training/runs/<UUID>`，比較文件在 `runtime/training/evaluations/<請求 UUID>`，安裝權重及 sidecar 在受管理 `runtime/ComfyUI/models/loras`。它們**不在 DATA 備份內**，須與原資料包、環境／基底一起備份。比較保存中斷可能已有部分方案；保留 evaluation 及原方案 UUID，依 T04 CLI 人工核對，不自動重試或刪除。

原生租約不跨 Docker，也不是整張 GPU 隔離。入口沿用 D01 的 peer／Host／Origin 保護，同機使用者及程式仍視為可信。新介面不增加作者圖來源權利或品質認列；有限實測見 [T06 驗收](../validation/training-control-20261025.md)。
