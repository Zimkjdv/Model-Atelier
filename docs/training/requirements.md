# T01 · 訓練需求與驗收範圍 v1

日期：2026-10-23。需求版本：`anime-training-requirements-v1`。T01 完成需求決策；**尚未開始訓練，沒有新增訓練端點、安裝 trainer 或更新模型權重**。使用者指定的開發順序維持 **T01 → T02 → R01 → R03**，實際執行訓練、GPU 協調及產物回登另屬 T03／T04。

## 決策與依據

使用者目標是指定作者畫風，以及已確認的「棕色長髮、綠眼、綠色髮飾」角色。作者標籤沿用已提供資料夾，角色正式名稱未獨立確認。圖片位置、22 檔／20 不同內容及每次單張參考的事實見 [圖片用途紀錄](../validation/reference-inputs-20261023.md)。

[R02 的 12 組結果](../validation/reference-adapter-20261023.md) 已證明單張參考能影響生成，卻存在兩種不同缺口：畫風模式帶入粉髮、服裝、吹泡泡及背景；角色模式較延續外觀，但同時帶入條紋／短裙，場景與物件服從仍不穩定。因此本輪工程決策是**規劃兩條可分開評估的 SDXL LoRA 候選路徑**，先做畫風試訓的資料及工具準備，再做角色；不把作者與同作者所有人物混成同一身份，不直接訓練單一「畫風＋角色」產物。

這是針對已知缺口的候選決策，並非已證明訓練優於提示詞或 adapter，也不是使用者對生成品質的簽認。若資料或 T03 實測顯示無法合理試訓，保留現有推論流程，記錄原因，不把需求決策當作訓練成功。

| 路徑 | 要學習與維持 | 不應隨之固定的內容 | 第一輪產物目標 |
| --- | --- | --- | --- |
| 畫風 | 線條、上色、陰影、高光及造型表現；能適用不同人物與場景 | 來源人物髮色、眼色、衣著、吹泡泡、背景文字或原構圖 | 單獨的畫風 LoRA 候選與固定比較紀錄 |
| 角色 | 目標的長髮、綠眼、綠髮飾及臉部／髮型特徵；跨場景外觀可辨識 | 參考圖的條紋服裝、短裙、固定姿勢、白底或其他角色 | 單獨的角色 LoRA 候選與跨場景比較紀錄 |

兩條路徑各自通過前，不評估疊加；產物即使可由 ComfyUI 載入，也不能直接標為畫風或角色品質通過。

## 推論調整與訓練的界線

| 操作 | 目前狀態／意義 |
| --- | --- |
| 修改 prompt、seed、steps、CFG、sampler、scheduler | 推論參數調整，不更新權重 |
| 使用現有 LoRA、變更順序或強度 | 載入既有權重進行推論，不是訓練 |
| R02 每次使用一張參考圖，選模式／權重／起訖 | adapter 推論條件；沒有把 20 張圖全送入，也沒有學成新 LoRA |
| 整理原圖、去重、caption、分組／版本與匯出資料包 | T02 的資料準備，不能因此宣稱模型已學習 |
| 對指定資料執行 optimizer 更新並產生新權重 | 實際訓練；本輪未執行，須由 T03 的獨立環境及明確 run 承接 |
| 將新權重登記模型庫並重新評估 | T04；載入相容、來源可追溯與品質三者分開驗收 |

## 可追溯與可執行的驗收方案

保留既有四項人工評分：`prompt_adherence`、`character_consistency`、`visual_style`、`composition`；未知或不適用填 `null`，並寫原因。**不自動打分，不用總分掩蓋內容帶入，也不把逐像素相似當成畫風或身份成功。**

### 固定比較配置

- 首輪以基底空 LoRA 與單一新 LoRA 作一對；同一對的提示詞、精確 seed、尺寸、取樣與負面提示相同，先不加 adapter／Canny／其他 LoRA。
- 起始推論基準沿用 R02：1024 × 1024、28 steps、CFG 5、`euler_ancestral`／`normal`、空 latent、denoise 1。這是比較基準，不是訓練超參數或通用品質推薦。
- seed 固定字串 `9007199254740993` 與 `18446744073709551615`。單 LoRA 初次候選設定規劃為 MODEL 1、CLIP 0；數值只作明確起點，不代表最佳強度，若調整須建立另一比較版本。
- 畫風使用既有 [動漫 v1 三題材](../../experiments/anime-illustration-v1.json)：肖像、全身、人物與車站背景；其黑短髮／眼鏡旅人與目標角色不同，用於檢查畫風是否綁定棕髮綠眼角色。實際 suite bytes／hash 與完整 prompt 必須凍結到未來 run。
- 角色使用 R02 的肖像、書店、公園題材，固定棕髮綠眼及綠髮飾，但要求一般完整藍外套、閉合紅書／閉合藍傘，檢查服裝、場景及物件是否仍可改變。完整 prompt 沿用 [R02 證據](../validation/reference-adapter-20261023.json)，不從檔名推測內容。
- **每條路徑 3 題材 × 2 seed × 2 分支＝12 件初次比較，兩條共 24 件計畫輸出**。不在 T01／T02 生成這批圖片，不建立自動批次；只有 T03／T04 的明確單次操作才建立任務。

### 必須分別判斷的條件

| 面向 | 通過範圍與保留證據 |
| --- | --- |
| 技術相容 | 基底、資料、trainer、完整設定及輸出 hash 可追溯；T03 能執行、停止、釋放 GPU，T04 新權重完整載入／保存／還原；這一欄不代替品質 |
| 畫風改善 | 六個題材／seed 格逐一並排基準與候選，人工檢查線條、陰影、高光及上色。至少四格明確較接近預先記錄的目標，其餘不得以未觀察冒充持平；記錄同時發生的內容偏移 |
| 角色改善 | 六格逐一核對外觀特徵及臉部／髮型延續；至少四格比空 LoRA 基準更接近目標，並檢查兩個 seed 與三個場景皆有代表，不用單張肖像代替跨場景結論 |
| 提示服從與內容分離 | 每格記錄人物數、髮色／眼色、服裝、物件狀態及背景。未要求的吹泡泡、原服裝、原構圖或文字帶入須列為偏差，不因畫風較像就忽略 |
| 絕對品質與相對改善 | 基準也失敗時兩者都記錄；「不比基準差」不等於絕對品質通過。存在未解的人物數／身份／服裝等關鍵錯誤時，不能稱為穩定可用或通用預設 |
| 評估完整性 | 四面向分開記錄，無自動分數或事後改標準；未做的面向保持未評分。所有原圖、失敗、prompt、模型／資料／工具／seed 及 workflow 保存，最後主觀品質仍需使用者檢視 |

「至少四格」是本專案預先定義的第一輪**改善訊號門檻**，不是模型能力、身份鎖定或使用者品質簽認；仍需逐格揭露失敗，T04 不得只挑成功圖。若效果不足，回到開發資料與假設重新建 run；不修改已凍結評估圖或舊結果。

## 圖片、分割與提醒時點

現有 20 個不同檔案內容不等於 20 件獨立原作，也不是同一角色訓練集。R02 的重複／差分群組及 6 張保留圖須沿用；不能把同圖裁切或差分分到訓練與評估兩邊。角色樣本逐張辨識，未確認者不能因同作者標籤而自動入選。

R02 已人工看過的圖片應保存曝光紀錄。現有保留圖仍不進訓練，但不自稱從未看過的盲測集；若反覆用來選訓練配置，應標為開發評估，T04 另需未參與選型／調參的最終保留圖。

**目前不要求使用者先補齊圖片才能完成 T01。** T02 先核對既有資料並產生缺項清單；真正準備試訓時，才就不足的同角色視角／服裝／場景、內容標註或來源資訊提醒補齊。進入 T04 最終比較時，再提醒確認獨立評估圖。張數是依驗收覆蓋決定的起始配額，不宣稱任何固定張數足以成功。
