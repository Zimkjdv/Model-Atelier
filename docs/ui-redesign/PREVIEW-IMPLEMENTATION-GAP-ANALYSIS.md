# 正式平台與核准預覽的落差分析

日期：2026-10-29。比對基準：正式程式 `3d55c0c`、[preview.html](preview.html)、[PLAN.md](PLAN.md) 與 [FEATURE-INVENTORY.md](FEATURE-INVENTORY.md)。

後續狀態：使用者已授權先修正 G01–G04，實作與正式環境實圖驗證見 [主要流程補齊紀錄](PRIMARY-FLOWS-IMPLEMENTATION.md)。以下保留原分析當時的缺口與證據，不把它誤作最新未完成清單。

## 結論

使用者指出的問題成立：目前差異不全是因為真實資料、相容性限制或合理優化。有些預覽已提供的操作沒有接入正式版，有些只完成預設頁面，其他分類或階段仍沿用舊介面。

最重要的缺口是：**創作台主畫布沒有接入生成結果、模型庫其他分類沒有清單／卡片切換、素材詳情視窗沒有實作**。作品庫另缺卡片評分／日期、每頁筆數選擇與搜尋無結果時的清除篩選入口。這些不應用「配色已套用」或「功能測試已通過」視為完成。

本文件只分析與建議，沒有修改正式平台，也沒有修改預覽來消除差異。

## 比對方法與界線

- 讀取八個主要頁面的入口、相關 Vue 元件、共用 `redesign.css`、預覽的實際輸出函式及規劃要求；對可疑缺口追查事件與子元件，區分「沒有功能」和「功能換了位置」。
- 預覽含有多輪追加覆寫。例如作品庫應以第 381 行開始的 `library=function...`、素材以 `assetLibrary()`、作品詳情以後面的 `detail=function...` 為準，不能用前段舊版函式作結論。
- 以下行號是本次版本的定位提示。連結指向原始檔；後續修改可能使行號移動。
- 本次是**原始碼與規格交叉核對**，沒有重新啟動正式服務、操作正式資料、執行 GPU 任務，亦沒有重新做瀏覽器逐像素比對。已有截圖與先前測試紀錄不能當作本次完整視覺驗收。
- P1：主要操作流程或明確核准的頁面能力未接齊；P2：資訊呈現、次要入口或便利操作落差。這不是資安風險等級。
- 「遺漏」指相對核准預覽／規劃未交付，不等同已證明刪除了舊版既有功能。除非有版本追溯證據，不宣稱是刪除回歸。

## 一、確認的遺漏與接線問題

### G01／P1：創作台主畫布只有空狀態，沒有完成結果

**核准要求：** PLAN §5.1（第 115 行）明定畫布顯示實際輸入／輸出、尺寸與狀態；作品入庫仍須另外明確匯入。預覽的主要舞台則以圖片展示預期呈現。

**正式現況：** [StudioPreview.vue](../../frontend/src/StudioPreview.vue) 只接受 `width`、`height`、`title`、`family`，模板固定輸出「準備下一張作品」，沒有圖片來源或任務結果輸入。[CreationStudio.vue](../../frontend/src/CreationStudio.vue) 第 1263–1279 行把這個空畫布和 `GenerationPanel` 分開掛載；[FluxStudio.vue](../../frontend/src/FluxStudio.vue) 第 488 行、[ReferenceStudio.vue](../../frontend/src/ReferenceStudio.vue) 第 521 行也使用此元件。

[GenerationPanel.vue](../../frontend/src/GenerationPanel.vue) 第 331–353 行提供最近任務／歷史入口，第 625 行附近提供完成後前往作品庫的事件，但未把完成圖片傳回上述主畫布。

**判定：** 結果呈現未整合，不只是「正式版不能放示意圖」。沒有任務時顯示空畫布正確；完成後仍然只有空畫布才是缺口。局部修補的遮罩畫布、結構流程的條件預覽應分別看待，不能概括說所有流程都沒有圖片。

**修正與驗收：** 主舞台接入使用者選定／最近完成任務的實際結果，顯示該結果本身的尺寸、任務身分與保存狀態；修改表單尺寸不能扭曲舊結果。未完成、離線、原圖不可讀時各有明確狀態。顯示結果不應自動匯入作品庫。

### G02／P1：模型庫的清單／卡片只完成 Checkpoint

**核准要求：** 預覽 `models()` 第 215–221 行以同一個 `ui.modelView` 套用各分類；PLAN §5.4 要求五類模型使用同一視覺系統、清單預設及卡片切換。

**正式現況：** [ModelLibrary.vue](../../frontend/src/ModelLibrary.vue) 第 206 行明確以 `v-show="category === 'checkpoint'"` 限制切換器；第 244 行的 `view` 只控制 Checkpoint 容器。第 471–502 行另外掛載 LoRA、ControlNet、參考元件與 FLUX 元件庫，沒有傳遞版型狀態。

[LoraLibrary.vue](../../frontend/src/LoraLibrary.vue) 第 149 行、[ControlLibrary.vue](../../frontend/src/ControlLibrary.vue) 第 88 行各有自己的 grid；[FluxComponentLibrary.vue](../../frontend/src/FluxComponentLibrary.vue) 第 49 行使用自己的元件列。[ReferenceLibrary.vue](../../frontend/src/ReferenceLibrary.vue) 則直接重用參考元件編輯器。

**判定：** 類別功能還在，但跨分類版型切換直接遺漏；不是單純圖片或資料不同。其他分類仍有自己的同步、說明與管理排列，也沒有完整採用預覽的共用模型列。

**修正與驗收：** 五類都能清單／卡片切換並預設清單，切換不遺失搜尋、編輯或選取。資料、授權、相容性與驗證紀錄保留於具名詳情；不能為了外觀刪除原能力。預覽中的非 Checkpoint「套用到創作」多為示意按鈕，是否新增真實跨頁套用應另外定義，不能假裝既有能力已接通。

### G03／P1：模型頁頂部同步按鈕沒有跟隨分類

**正式現況：** [ModelLibrary.vue](../../frontend/src/ModelLibrary.vue) 第 188–192 行的「同步模型清單」在所有分類上方顯示，固定呼叫 `load(true)`；第 100–122 行的請求固定走 `/api/models/sync`。LoRA、ControlNet、參考元件、FLUX 又各自提供專用同步按鈕。

**判定：** 共用外觀與實際操作對象未對齊。切到 LoRA 等分類後，頁首同步仍是 Checkpoint 同步；不能把它當成當前分類或全部模型的同步。

**修正與驗收：** 頂部按鈕跟隨當前分類，或清楚標示只同步 Checkpoint 並調整位置。逐一切換五類，確認按鈕名稱、忙碌狀態、錯誤及請求端點一致，避免同頁兩組含義不清的同步入口。

### G04／P1：參考素材缺少點圖後的詳情視窗

**核准要求：** 預覽第 377–379 行：點擊素材開啟 `assetDetail()`，包含圖片、用途、尺寸、用於創作、編輯／封存入口。PLAN §5.3 也規劃素材詳情。

**正式現況：** [AssetLibrary.vue](../../frontend/src/AssetLibrary.vue) 第 202–203 行把圖片直接連到 `/api/assets/{id}/image`，以新分頁開啟原圖。名稱／用途編輯、封存及前處理版本則留在卡片的「素材管理」展開區（第 204–261 行）。

**判定：** 詳情視窗與操作集中方式沒有實作；不是素材編輯或封存能力整個消失。開新分頁看原圖可當附加功能，但沒有提供預覽要求的詳情體驗。

**修正與驗收：** 點圖先開素材詳情，保留獨立開啟原圖入口；尺寸、用途、前處理資訊與操作集中，關閉後回到原卡片及捲動位置。保留未保存編輯保護。

### G05／P2：作品庫的資訊與清單控制沒有全部搬入

| 項目 | 預覽／規劃 | 正式現況與證據 | 判定 |
| --- | --- | --- | --- |
| 卡片評分與日期 | 預覽第 389 行有評分／尚未評分及日期；PLAN §5.2 明列日期 | [ArtworkLibrary.vue](../../frontend/src/ArtworkLibrary.vue) 第 713–765 行只以標題、模型、尺寸作卡片摘要；展開區亦無對應評分／日期列 | 卡片資訊遺漏；詳細人工評分功能仍在，不是評分資料消失 |
| 每頁筆數 | 預覽第 390 行提供 4／12／24 選擇 | 第 659–662 行以固定 40 計算頁數；第 770–782 行只有前後頁 | 選擇器遺漏；分頁本身有實作。正式值不一定要照抄示例，但需有可選筆數才能稱功能對齊 |
| 符合數／全部數 | 預覽第 388 行同時列符合與全部作品數 | 第 659–662 行只有符合數、目前頁與本頁張數 | 總覽資訊少一項；不能誤稱完全沒有總數 |
| 無結果清除篩選 | 預覽第 389 行提供按鈕；PLAN 第 127 行明訂 | 第 672–678 行只有文字提示使用者調整搜尋 | 快捷操作遺漏；使用者仍可逐個手動清除 |

**修正與驗收：** 補回卡片摘要、筆數控制、清楚定義的總數與清除按鈕。評分須說明如何由正式版多項人工評分形成摘要，不能任意用其中一個數字冒充總分；分頁筆數改動需與後端游標契約一致。

### G06／P2：參考素材搜尋無結果缺少清除篩選

預覽 `assetLibrary()` 第 377 行有 `data-asset-clear`；[AssetLibrary.vue](../../frontend/src/AssetLibrary.vue) 第 196–198 行只有「上傳圖片，或調整搜尋與封存篩選」。此項與詳情視窗不同，是另一個遺漏的空狀態操作。

**驗收：** 搜尋無結果時可一鍵清除搜尋與用途條件；封存範圍是否一起重置須明示，並遵守未保存編輯保護。空庫與搜尋無結果不應都只給相同的上傳提示。

## 二、部分完成，不能籠統當作已對齊

### P01／P1：預檢沒有完整採用「阻擋原因＋欄位錯誤」

預覽第 349–350 行以 `preflightMarkup()` 列阻擋清單、`fieldFeedback()` 把錯誤放在相應欄位下。[CreationStudio.vue](../../frontend/src/CreationStudio.vue) 第 228 行起的 `submissionBlock` 則依條件回傳一個字串；[GenerationPanel.vue](../../frontend/src/GenerationPanel.vue) 第 309–315 行集中顯示 `blockedReason`／請求錯誤，依關鍵字附上設定／模型連結。

**判定：** 真實預檢與部分處理入口存在；沒有證據說驗證被刪除。但至少 Checkpoint 主流程未交付預覽那套完整欄位對應與多原因呈現。各流程已有的專用錯誤應保留，不宜未逐一驗證就宣稱全部都沒有。

**驗收：** 同時存在欄位問題與環境阻擋時，各自出現在正確位置；欄位可聚焦、展開並修正，環境連結導向實際處理頁。保留後端最終驗證。

### P02／P2：訓練「執行與產物」沒有對齊預覽的進度摘要

預覽 `training()` 第 231 行有大字「目前／總 steps」、進度條，以及分開的執行／完成後區塊。

[TrainingControl.vue](../../frontend/src/TrainingControl.vue) 第 438–469 行仍先顯示 run 登記、run 選擇、報告與 UUID，再以一般段落顯示「更新步數」。此元件沒有對應的訓練步數進度條。停止、日誌、產物及固定比較仍保留（第 477 行以後），不能列為功能消失。

**判定：** 審查階段的新版進度／縮圖已做，但執行階段的核心視覺摘要未接齊。這是呈現遺漏，不是訓練控制器不存在。

**驗收：** 有 run 時以真實步數與上限呈現摘要及進度，未知時顯示未知；完整 UUID、恢復、日誌及產物放下方具名區域。不得填入預覽的 620／1000 假進度。

### P03／P2：設定的「匯出設定」入口缺少，但創作設定匯出仍在

預覽 `settings()` 第 289 行的資料與隱私面板有「匯出設定」示意入口。正式 [App.vue](../../frontend/src/App.vue) 第 474–487 行只有隱私／備份說明與資料位置入口。

另一方面，[SettingsTransfer.vue](../../frontend/src/SettingsTransfer.vue) 第 183 行起已有創作參數匯出／匯入，[CreationStudio.vue](../../frontend/src/CreationStudio.vue) 第 1223 行仍掛載它。

**判定：** 缺少設定頁的引導入口，不是全平台無法匯出。預覽按鈕本身是示意，不能推論已有「整个平台完整設定備份 API」卻遭刪除。

**驗收：** 若此處指創作參數，提供到現有交換功能的清楚入口；若要匯出平台設定，另定欄位、敏感資訊與匯入契約。勿把參數匯出當成作品／模型備份。

## 五、為什麼先前通過檢查仍有遺漏

1. **位置測試不等於功能清單驗收。** [preview-alignment.spec.ts](../../frontend/tests/preview-alignment.spec.ts) 的 `aligned()` 主要比較 x、y、width；共用檢查還包括欄數、側欄背景與第一個圖示寬度。這能驗證被測位置，不能證明每個按鈕、資訊列及後續狀態都有交付。
2. **模型測試集中在預設 Checkpoint。** 同檔模型段切換預設頁的清單／卡片，沒有據此驗證其他四類也能切換，所以 G02 可在這組測試通過時仍存在。
3. **創作畫布測試比較的是空畫布幾何。** 同檔把 `.empty-canvas` 與預覽 `.image-frame` 比較，沒有證明生成完成後主舞台會換成結果圖。這是 G01 的驗收缺口。
4. **入口整合與子頁整合深度不同。** `ModelLibrary`、`TrainingWorkspace` 掛入既有管理元件，保住原功能，但子分類／後段階段沒有全部套入核准呈現。
5. **整合紀錄描述過於概括。** 「作品庫已整合」「模型可切換卡片」這類說法應補適用範圍與未完成項目。歷史測試結果應保留，不能反過來當作所有需求皆完成的證據。

上述是根據測試實際斷言與元件接線作出的分析，不推測開發者的主觀動機，也不代表其他測試全部無效。
