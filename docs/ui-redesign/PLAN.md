## 1. 要解決的問題與設計方向

平台功能已經豐富，但目前較像工程操作面板：同等重量的卡片、技術名稱、說明與操作大量並列，使用者必須先理解系統，才能開始創作。這次建議以「創作工作室」重新組織：作品是主角，設定在旁，下一步清楚可見。

採用使用者偏好的深色方向：墨黑背景、深灰綠卡片、淺灰白文字與低飽和綠色主操作。保留原平台的深色氣質，透過字級、留白、邊框與資訊分組改善辨識。重要硬體與環境資訊預設展開；「減少雜亂」不得變成刪除能力或把主要資訊藏起來。

核心原則：

- 每頁一個明確目的、一個主要操作；其他動作依情境出現。
- 先用使用者語言選目的，再顯示模型與技術選項。
- 常用設定直接可見，進階參數可展開，技術追溯資訊放詳情。
- 作品、參考素材、訓練圖片明確分工；相互轉用必須明確操作。
- 連線成功、模型已登記、流程可執行、實機驗證通過是不同狀態，不能混成綠色「可用」。
- 保留草稿、來源、未知值、原請求恢復、人工匯入與明確啟動等現有保護。

## 4. 共用版面與視覺規格

### 4.1 框架

- 桌面採範例的 72px SVG 導覽欄，保留簡短中文標籤、完整無障礙名稱與 tooltip；圖示統一線寬。窄版變成可橫捲的文字圖示列。
- 頂列只放目前頁面、引擎狀態、預覽情境及原型說明。工作台不再放大標語；其他頁標題約 26–28px。移除全大寫英文 eyebrow、無順序意義的任務編號與裝飾字樣。
- 一般頁內容左右間距約 28–32px，工作台直接滿版分欄；卡片內距 20–24px；8px 間距系統，避免每個元件各自決定距離。
- 一頁一個主標題，區塊標題 17–20px；內容 14–16px，次要說明通常至少 13px（窄導覽任務標籤例外為 12px），繁體中文行高約 1.6；技術碼／seed 才用等寬字。
- 卡片深灰綠底、1px 灰綠邊框、12–16px 圓角。陰影只用於浮層；不要讓所有容器都像按鈕。
- 主操作淺綠實心搭配深色文字，次要操作深底描邊；危險操作放次級選單或相關階段，不與主要操作搶視線。
- 近黑大畫布佔據右側主要面積，設定欄約 340–410px；移除畫布外多餘卡片層與長說明。主操作固定在設定欄底部，任務列縮為一行主狀態＋下一步；窄版按順流排版避免遮住內容。

### 4.3 響應式與無障礙

- ≥1280px：設定約 340–410px、畫布自適應雙欄；圖庫 3–4 欄。
- 900–1279px：保留導覽文字，縮減留白；圖庫 2–3 欄。
- <900px：導覽轉頂部可換行區，內容單欄，設定、預覽與任務依順序呈現。
- 390px：不得整頁橫向溢出；大型表格可局部橫捲且可鍵盤聚焦。主操作不得蓋住欄位。
- 一般文字對比至少 4.5:1；控制邊界與焦點至少 3:1；按鈕觸控目標優先 44px。
- 圖示附名稱；狀態同時有文字；錯誤連到欄位，操作結果用 status 公告。彈窗應限制焦點並支援 Escape、返回原觸發點。
- 尊重減少動態效果。實作驗收仍需實際鍵盤、讀屏及觸控檢查，不能以預覽取代。

## 5. 各頁詳細作法

### 5.1 創作工作台

首屏固定為「任務選擇 → 設定／畫布 → 提交結果」。將現有五流程呈現為文字創作、圖片重繪、局部修補、結構引導、畫風／角色參考。前兩個是使用者目的，不代表新增引擎；其下再選相容的 Checkpoint／SDXL 或 FLUX。

| 任務名稱 | 既有能力映射 | 專屬設定 | 必須保留的限制 |
| --- | --- | --- | --- |
| 文字創作 | checkpoint 或 flux 文生圖 | 模型、提示詞、尺寸 | FLUX 專用元件與參數，不套用 SDXL 的通用預設 |
| 圖片重繪 | checkpoint 單張圖生圖／FLUX VAE 圖生圖 | 輸入圖、重繪強度 | 不等同鎖定人物身分；不同架構分別驗證 |
| 局部修補 | inpaint | 大畫布遮罩、筆刷、反相、羽化與模式 | 專用草稿／交換能力仍有限；遮罩需明確保存 |
| 結構引導 | control | Canny／pose／depth、來源圖與條件預覽 | 依模型與預處理器能力顯示，不把 Canny 當作唯一結構流程 |
| 畫風／角色參考 | reference | 單張參考圖、模式、權重 | 無身份鎖定；不得暗示全部素材一起參與訓練 |

設定依目的／來源 → 描述 → 模型 → 尺寸 → 進階排序。尺寸按鈕顯示正確比例、寬高與 MP；來源圖不合規時先展示縮放／補邊／裁切選項，不靜默變形。模型建議尺寸、API 合法尺寸與硬體已驗證配置分開呈現，不能用架構名稱推定全域 MP 上限。

設定區第一層只顯示必要項目；負面詞、steps、CFG、sampler、scheduler、seed、LoRA 排序放進階區，摘要顯示目前值。seed 始終以字串保存。已手動修改的值不得因換模型而靜默覆蓋；預設必須先比較再明確套用。

畫布區顯示實際輸入／輸出、尺寸與狀態；生成中顯示真實進度或「等待引擎」，沒有資料時不要造倒數時間。下方任務區提供查看詳情、原請求恢復、條件式停止與「前往作品庫匯入」。不得把完成任務直接宣稱成已保存作品。

主操作前緊鄰顯示預檢結果，只有真正阻擋條件才停用；可修正原因提供入口。生成／訓練忙碌和連線不明需分別處理。一般提示不必反覆佔據整屏。

草稿列移到標題旁，明示「未保存／已保存」；切換任務保留各自表單，並遵守現有 pending request 與 dirty 保護。能力不支援時不顯示假的「保存草稿」按鈕。

### 5.2 作品庫

提供瀑布流／固定排版切換；瀑布流保留真實比例，固定方格只裁切縮圖。兩種版型共用搜尋、模型、收藏／封存與最多四張選取比較，切換不清空選取；標題、模型及日期各一行，收藏與狀態只保留少量標記。搜尋、收藏、封存、排序集中一列。匯入任務結果與上傳參考素材不混用名稱。

開啟作品後，左側大圖，右側用「資訊／生成設定／來源」組織既有筆記、評分、原設定、workflow 與技術記錄。主動作為「載入原設定」，清楚說明不會自動生成。比較時顯示選取數量與取消選取，真實比例並排；固定參數實驗則固定相同尺寸。詳情顯示寬、高及像素量；不新增批量生成。

空庫：說明先生成再明確匯入。搜尋無結果：提供清除篩選。縮圖失敗：保留作品卡及可辨識錯誤，不能把作品當作不存在。

### 5.3 參考素材

上傳入口縮至工具列；空庫時才放大型上傳引導。首屏以圖片與用途標籤呈現：重繪、結構、畫風、角色等（正式值沿用現有契約）。詳情列出尺寸、正規化處理、用途、引用情況及相容流程。

「用於創作」是建議增加的跨頁操作：先選流程，再明確帶入素材 ID；不自動提交、不暗改模型。用途標籤僅整理用途，不宣稱能鎖定角色。上傳限制沿用 PNG／JPEG／WebP、20 MiB、1600 萬像素與正規化說明，正式上傳依目前單張能力設計。

### 5.4 模型庫

以 Checkpoint、LoRA、結構控制、參考元件、FLUX 元件分類檢視；沿用各類別實際同步／登記能力，不能把「同步清單」包裝成自動安裝。

每張卡顯示名稱、架構、支援任務、登記狀態；缺少元件以具體清單及修正入口呈現。來源、授權、hash 放詳情且可查，不刪去既有證據缺口。「套用到創作」建議新增為明確流程，先檢查相容性，再顯示設定差異，最後由使用者確認。

### 5.5 訓練工作區

頂部階段列「審查資料 → 匯出資料包 → 準備訓練 → 執行與產物」。它是導航與進度摘要，不代表每次按下一步都會啟動運算。

審查頁：左側待審圖片與缺項篩選，中間大圖，右側 caption、來源、角色與分組；保存／上一張／下一張固定在表單尾端。缺項摘要可定位到該張圖片與欄位。訓練／開發評估／排除集合用文字區分，不依顏色判斷。

執行頁：分開「準備 run」與「開始訓練」；清楚顯示凍結版本、資源條件、互斥狀態與停止結果。回應不明時查回原 UUID，不重送。續訓建立新 run 並連回來源，不覆蓋舊紀錄。產物安裝、模型回登與固定比較各自有明確操作。

預覽僅示意資料缺項與 run 進度，不表示本機真實資料通過，也不表示已進行作者風格訓練。

### 5.6 實驗比較（新入口，重用既有功能）

將現有方案、分組、結果與報告整理成獨立頁。先選比較軸與固定條件，顯示預計組數及每次一張，再保存方案。結果用矩陣／並排圖呈現：每格可為未開始、執行中、待匯入、已完成或失敗。

選取一組後可載入其設定，仍由使用者手動生成。提供人工評分與差異摘要，未知值顯示未知。不增加自動重試、批次調度或 AI 品質評分。既有工作台入口可改為導向此頁並帶入設定快照。

### 5.7 系統資訊（v2 重整，保留完整原有能力）

本頁不能只顯示三個摘要卡。改成五個預設展開的大區塊，頁首用頁內定位連結快速跳轉；詳見功能對照 E01–E13、S01–S04。

1. **平台主機**：主機名／原生或容器／更新時間；每張 GPU 名稱、索引、專用顯存可用／總量／已用及驅動；RAM 可用／總量／已用；資料所在磁碟可用／總量／已用。補上 OS、平台 Python、資料目錄。保留 15 秒更新與過期錯誤，GPU 失敗不影響其他卡片。
2. **選定引擎的執行環境**：URL、查詢時間、來源與狀態；ComfyUI／Python／PyTorch／CUDA runtime／CUDA 是否可用／驅動／OS／RAM；各裝置名稱、類型、索引、VRAM 與 Torch 記憶體；設定執行裝置狀態、來源、原因與 warnings。資料必須匹配選定 URL，不能用平台 GPU 補遠端引擎資料。
3. **目錄與磁碟容量**：合計可用／總量／磁碟數、部分未知與快照時間；每磁碟容量、使用比例及所屬目錄；每個目錄保留 role、登記路徑、實際路徑、狀態、錯誤及開啟資料夾按鈕。多目錄同磁碟不可重複加總，≥90% 使用率沿用警示。更新容量與開啟資料夾各有忙碌／錯誤狀態。容量是磁碟容量，不是資料夾遞迴佔用量。
4. **本機 ComfyUI 安裝檢查**：保留檢查按鈕、Python 路徑、上次檢查、套件／CUDA／驅動／裝置及警告。此為本專案管理環境，與選定引擎獨立；容器不能直接檢查 Windows 原生環境。
5. **部署與存取**：本機／容器、本機／外部引擎、URL、資料保存角色、更新操作與本機信任邊界。

即時環境與歷史任務分開：提交時版本／依賴／裝置／效能條件仍留在任務和作品詳情；耗時與連續資源取樣保留原引擎來源、起訖、失敗、間隔與觀察最高值。不把現在的值填入歷史，也不把觀察最高值說成任務專用峰值。

### 5.8 設定（v2 補回原有模型目錄編輯）

三個子區為引擎連線、本機模型目錄、診斷。模型路徑不是唯讀文字：保留額外 checkpoint 目錄每行一個、最多 8 個、保存／重新讀取、dirty／衝突／捨棄確認、保存修訂時間，以及預設與額外目錄的磁碟狀態。預設目錄固定保留；沿用既有搜尋順序、同名檔優先與手動重啟後同步提示。

「只作用於本專案受管理的本機引擎」必須直接顯示，不可暗示會改遠端引擎路徑。系統資訊的目錄區提供到此表單的入口。診斷保留唯讀檢查、識別資料、JSON 安全預覽與下載完全相同快照。備份仍沿用停機工具流程。

## 7. 關鍵狀態與文案

| 狀態 | 畫面處理 | 可採取動作 |
| --- | --- | --- |
