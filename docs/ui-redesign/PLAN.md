## 1. 要解決的問題與設計方向

平台功能已經豐富，但目前較像工程操作面板：同等重量的卡片、技術名稱、說明與操作大量並列，使用者必須先理解系統，才能開始創作。這次建議以「創作工作室」重新組織：作品是主角，設定在旁，下一步清楚可見。

採用使用者偏好的深色方向：墨黑背景、深灰綠卡片、淺灰白文字與低飽和綠色主操作。保留原平台的深色氣質，透過字級、留白、邊框與資訊分組改善辨識。重要硬體用量與整體狀態預設可見，詳細環境與路徑依最新參考放入具名分頁或展開區；「減少雜亂」不得變成刪除能力。

核心原則：

- 每頁一個明確目的、一個主要操作；其他動作依情境出現。
- 先用使用者語言選目的，再顯示模型與技術選項。
- 常用設定直接可見，進階參數可展開，技術追溯資訊放詳情。
- 作品、參考素材、訓練圖片明確分工；相互轉用必須明確操作。
- 連線成功、模型已登記、流程可執行、實機驗證通過是不同狀態，不能混成綠色「可用」。
- 保留草稿、來源、未知值、原請求恢復、人工匯入與明確啟動等現有保護。

## 4. 共用版面與視覺規格

### 4.1 框架

- 桌面採範例的 72px SVG 導覽欄，保留簡短中文標籤、完整無障礙名稱與 tooltip；圖示統一線寬。本輪以桌面側欄為準。
- 頂列只放目前頁面、引擎狀態、預覽情境及原型說明。工作台不再放大標語；其他頁標題約 26–28px。移除全大寫英文 eyebrow、無順序意義的任務編號與裝飾字樣。
- 一般頁內容左右間距約 28–32px，工作台直接滿版分欄；卡片內距 20–24px；8px 間距系統，避免每個元件各自決定距離。
- 一頁一個主標題，區塊標題 17–20px；內容 14–16px，次要說明通常至少 13px（窄導覽任務標籤例外為 12px），繁體中文行高約 1.6；技術碼／seed 才用等寬字。
- 卡片深灰綠底、1px 灰綠邊框、12–16px 圓角。陰影只用於浮層；不要讓所有容器都像按鈕。
- 主操作淺綠實心搭配深色文字，次要操作深底描邊；危險操作放次級選單或相關階段，不與主要操作搶視線。
- 近黑大畫布佔據右側主要面積，設定欄約 340–410px；移除畫布外多餘卡片層與長說明。主操作固定在設定欄底部，任務列縮為一行主狀態＋下一步。

### 4.3 桌面視窗與無障礙

- 本輪以 1440×900 為主要設計尺寸，並規劃核對 1280×800、1920×1080 的桌面視窗；這些是後續驗收目標，不代表已在本次全部重測。
- 桌面保留 72px 側欄，創作頁維持左設定／右畫布；圖庫依可用寬度調整欄數，模型庫保留清單／卡片切換。
- 長路徑與檔名可換行，大型表格可局部橫捲且可鍵盤聚焦；彈窗及展開內容不可遮住主要操作。
- 一般文字對比至少 4.5:1；控制邊界與焦點至少 3:1。尺寸沿用已確認的參考，不因取消手機需求而縮小控件。
- 圖示附名稱；狀態同時有文字；錯誤連到欄位，操作結果用 status 公告。彈窗支援 Escape、焦點管理及返回原觸發點。
- 尊重減少動態效果，保留桌面鍵盤與必要讀屏檢查。手機／平板專用布局、行動觸控與實體手機測試不納入本輪。

## 5. 各頁詳細作法

### 5.1 創作工作台

首屏固定為「任務選擇 → 設定／畫布 → 提交結果」。將現有五流程呈現為文字創作、圖片重繪、局部修補、結構引導、畫風／角色參考。前兩個是使用者目的，不代表新增引擎；其下再選相容的 Checkpoint／SDXL 或 FLUX。

| 任務名稱 | 既有能力映射 | 專屬設定 | 必須保留的限制 |
| --- | --- | --- | --- |
| 文字創作 | checkpoint 或 flux 文生圖 | 模型、提示詞、尺寸 | FLUX 專用元件與參數，不套用 SDXL 的通用預設 |
| 圖片重繪 | checkpoint 單張圖生圖／FLUX VAE 圖生圖 | 輸入圖、重繪強度 | 不等同鎖定人物身分；不同架構分別驗證 |
| 局部修補 | inpaint | 大畫布遮罩、筆刷、反相、羽化與模式 | 專用草稿／交換能力仍有限；遮罩需明確保存 |
| 結構引導 | control | Canny／pose／depth、來源圖與條件預覽 | 依模型與預處理器能力顯示，不把 Canny 當作唯一結構流程 |
| 畫風／角色參考 | reference | 單張參考圖、模式、權重 | 無身份鎖定；不得暗示全部素材一起參與訓練 |

設定依目的／來源 → 描述 → 模型 → 尺寸 → 進階排序。尺寸按鈕顯示正確比例、寬高與 MP；來源圖不合規時先展示縮放／補邊／裁切選項，不靜默變形。模型建議尺寸、API 合法尺寸與硬體已驗證配置分開呈現，不能用架構名稱推定全域 MP 上限。

設定區第一層只顯示必要項目；負面詞、steps、CFG、sampler、scheduler、seed、LoRA 排序放進階區，摘要顯示目前值。seed 始終以字串保存。已手動修改的值不得因換模型而靜默覆蓋；預設必須先比較再明確套用。

畫布區顯示實際輸入／輸出、尺寸與狀態；生成中顯示真實進度或「等待引擎」，沒有資料時不要造倒數時間。下方任務區提供查看詳情、原請求恢復、條件式停止與「前往作品庫匯入」。不得把完成任務直接宣稱成已保存作品。

主操作前緊鄰顯示預檢結果，只有真正阻擋條件才停用；可修正原因提供入口。生成／訓練忙碌和連線不明需分別處理。一般提示不必反覆佔據整屏。

草稿列移到標題旁，明示「未保存／已保存」；切換任務保留各自表單，並遵守現有 pending request 與 dirty 保護。能力不支援時不顯示假的「保存草稿」按鈕。

### 5.2 作品庫

預設使用「固定排版」，並提供瀑布流切換；瀑布流保留真實比例，固定方格只裁切縮圖。兩種版型共用搜尋、模型、收藏／封存與最多四張選取比較，切換不清空選取；標題、模型及日期各一行，收藏與狀態只保留少量標記。搜尋、收藏、封存、排序集中一列。匯入任務結果與上傳參考素材不混用名稱。

開啟作品後，左側大圖，右側用「資訊／生成設定／來源」組織既有筆記、評分、原設定、workflow 與技術記錄。主動作為「載入原設定」，清楚說明不會自動生成。比較時顯示選取數量與取消選取，真實比例並排；固定參數實驗則固定相同尺寸。詳情顯示寬、高及像素量；不新增批量生成。

空庫：說明先生成再明確匯入。搜尋無結果：提供清除篩選。縮圖失敗：保留作品卡及可辨識錯誤，不能把作品當作不存在。

### 5.3 參考素材

上傳入口縮至工具列；空庫時才放大型上傳引導。首屏以圖片與用途標籤呈現：重繪、結構、畫風、角色等（正式值沿用現有契約）。詳情列出尺寸、正規化處理、用途、引用情況及相容流程。

「用於創作」是建議增加的跨頁操作：先選流程，再明確帶入素材 ID；不自動提交、不暗改模型。用途標籤僅整理用途，不宣稱能鎖定角色。上傳限制沿用 PNG／JPEG／WebP、20 MiB、1600 萬像素與正規化說明，正式上傳依目前單張能力設計。

### 5.4 模型庫

預設使用參考的清單風格，並可切換同一視覺系統的卡片。以 Checkpoint、LoRA、結構控制、元件（參考元件）、FLUX 元件分類檢視；沿用各類別實際同步／登記能力，不能把「同步清單」包裝成自動安裝。

清單與卡片共用相同模型、分類、名稱、架構、尺寸與登記狀態；缺少元件以具體清單及修正入口呈現。來源、授權、hash 放詳情且可查，不刪去既有證據缺口。「套用到創作」建議新增為明確流程，先檢查相容性，再顯示設定差異，最後由使用者確認。

### 5.5 訓練工作區

頂部階段列「審查資料 → 匯出資料包 → 準備訓練 → 執行與產物」。它是導航與進度摘要，不代表每次按下一步都會啟動運算。

審查頁：左側待審圖片與缺項篩選，中間大圖，右側 caption、來源、角色與分組；保存／上一張／下一張固定在表單尾端。缺項摘要可定位到該張圖片與欄位。訓練／開發評估／排除集合用文字區分，不依顏色判斷。

執行頁：分開「準備 run」與「開始訓練」；清楚顯示凍結版本、資源條件、互斥狀態與停止結果。回應不明時查回原 UUID，不重送。續訓建立新 run 並連回來源，不覆蓋舊紀錄。產物安裝、模型回登與固定比較各自有明確操作。

預覽僅示意資料缺項與 run 進度，不表示本機真實資料通過，也不表示已進行作者風格訓練。

### 5.6 實驗比較（新入口，重用既有功能）

將現有方案、分組、結果與報告整理成獨立頁。先選比較軸與固定條件，顯示預計組數及每次一張，再保存方案。結果用矩陣／並排圖呈現：每格可為未開始、執行中、待匯入、已完成或失敗。

選取一組後可載入其設定，仍由使用者手動生成。提供人工評分與差異摘要，未知值顯示未知。不增加自動重試、批次調度或 AI 品質評分。既有工作台入口可改為導向此頁並帶入設定快照。

### 5.7 系統資訊（以最新 system-page-redesign.html 為準）

本頁統一採 1120px 最大內容寬度、左右 32px 內距，說明、結論、三張摘要卡、分類列及內容面板共用左緣。只保留頂欄一個頁名；本頁頂欄 57px、標題 18px，其他頁維持已確認的 62px／20px。側欄 SVG 路徑、22×22px 尺寸、1.7px 線寬與 12px 標籤完全沿用參考；更新及開啟資料夾使用參考原始 SVG，18×18px、1.8px 線寬。一般按鈕 44px；小按鈕／圖示按鈕 36px，圖示按鈕保留可讀名稱。

摘要卡上方放整體結論。正常為「整體正常 · 1 項尚未檢查」；離線、缺元件或低容量時顯示需處理數量及暖色。空資料使用「資料待確認」，不以零容量或綠色已連線代替未知。頂部「示意資料」統一說明本頁性質，10:42 為展示時間，並非實際更新。

三卡採參考的 16px 欄距、20px 內距、14px 圓角、15px 標題、26px 主數值與 12px 狀態標籤。主機顯存及 RAM 寫成「已用 / 總量 GB · 百分比」，使用條與摘要連結沿用參考。儲存卡同樣呈現合計已用／總量與百分比，分段條與圖例依最新對比調整改為淺綠（模型 #b9d3a4）、淺青（作品 #90cbd2）、淡紫（其他 #c3b1d4），圖例以三欄並排，每欄分兩行：上行為分類名稱與對應色塊，下行為主要文字亮度的粗體 GB 數值；琥珀色用於需處理的狀態，不再用於一般環境說明。

下方五組功能改以四個分頁組織，預設總覽。分頁列固定在 57px 頂欄下方，具 tablist／tab／tabpanel、aria-selected、單一 Tab 入口，支援左右鍵及 Home／End。切換不改 #system、不增加 history；摘要連結會切到對應分頁並定位內容。

原範例只有五個目錄，本原型保留既有「受管理 ComfyUI 輸出」，因此正常摘要顯示「6 個目錄皆可讀」，不能為符合範例數量而刪去既有目錄。每個目錄列只顯示名稱、完整路徑與資料夾圖示按鈕，移除重複的「C: · 可讀／D: · 可讀」副行；可讀狀態集中在上方摘要。未知時摘要改為狀態待確認，資料夾按鈕停用；原型不開啟檔案總管。

正常數字維持主機顯存已用 4／總量 16 GB、RAM 已用 24／總量 64 GB；可用 12／40 GB 留在主機詳情。儲存合計 1,480／3,000 GB，模型 820 GB、作品 96 GB、其他 564 GB；可用 1,520 GB、磁碟區 2 個在儲存完整資訊。C: 已用 680／1,000 GB，D: 已用 800／2,000 GB。使用條採未四捨五入比例，文字百分比依參考取整數。

本頁新增「需要注意」展示情境：引擎離線且 C: 已用 930 GB／剩餘 7%。合計同步改為 1,730 GB、可用 1,270 GB、其他 814 GB，避免只改警示卻留下互相矛盾的容量；沒有真的變更磁碟或環境。既有正常／空資料／缺件／離線情境仍可切換。

參考未重做的 Torch 記憶體、GPU 查詢失敗、過期、容器與遠端部署差異均保留於對應分頁說明；這代表資訊與正式整合要求未刪除，並非已完成所有錯誤回報與真實探測。正式版需依 E01–E13、S01–S04 接回原有來源、更新、忙碌／失敗、部分未知及歷史快照規則。模型／作品分類仍屬 N07，只有範圍與讀值可靠時才計算其他；正式容量從 bytes 以 10^9 換算為 GB。歷史任務與作品資料仍與即時環境分開。

### 5.8 設定（v2 補回原有模型目錄編輯）

## 8. 原訂實作拆分（已依使用者授權開始，交付狀態見正式整合紀錄）

1. **確認方向**：看 HTML 的八個入口、工作台任務切換與空／錯誤狀態；確認視覺風格、命名、導覽與優先項。此步不碰正式程式。
2. **建立介面基礎**：共用 token、側欄、標題、按鈕與狀態元件；不重寫 API。先保留既有路由，再補新入口。
3. **完成創作主線**：工作台、作品、素材、模型；先做 V／F 項，再做跨頁 N 項，防止視覺與行為一起大改難以回歸。
4. **整理訓練與比較**：重用原資料與 run 契約；抽出頁面時保留 state ownership 和請求生命週期，必要時才評估 API 聚合。
5. **統一管理頁與全站狀態**：系統／設定、診斷、過期資料、空狀態與錯誤；確認證據文案。
6. **驗收與更新文件**：針對有改動的流程跑既有契約與瀏覽器檢查，再依整合風險跑完整品質檢查；更新教學截圖。不要為純樣式改動執行真實 GPU 訓練。

建議元件邊界：AppShell、PageHeading、StatusBadge、WorkflowPicker、CreationLayout、AssetPicker、ResultPreview、TaskSummary、LibraryToolbar、DetailPanel。只在實際重複時抽共用元件，不先建一整套泛用框架。
