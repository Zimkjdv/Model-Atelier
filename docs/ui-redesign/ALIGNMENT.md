# 正式介面與 preview.html 的對照修正

日期：2026-10-28。此紀錄補正 `22d0aef` 的介面整合；不更動已確認的 `preview.html`。

## 原因

前一次將配色、導覽及部分元件套入既有 Vue 頁面，卻保留了過多舊頁面的排列、工具列與預設展開狀態。功能與溢出檢查通過，並不能證明畫面符合預覽；先前缺少直接載入 HTML 並逐頁比對的驗證。

## 本次修正

| 頁面 | 原先差異 | 已調整 |
| --- | --- | --- |
| 創作工作台 | 保存說明與架構按鈕擠掉主要欄位；畫布偏小，任務資訊散落 | 五個任務圖示、簡短用途提示、必要欄位與尺寸按鈕回到預覽位置；架構選擇保留於小型選單，進階／草稿另展開；畫布依視窗及比例縮放，底部集中最近任務與歷史入口。 |
| 作品庫 | 排版、篩選、排序、分頁占用多排，圖片被往下推；固定圖框仍殘留 230px 高度 | 搜尋／收藏／封存／模型與排版合併為主要工具列；總數與排序採較小一行；分頁及補充管理移至內容下方。固定模式回到正方形，瀑布流以真實比例呈現且保留原 DOM 排序。詳情右上角的封存／關閉保留。 |
| 參考素材 | 能力說明、重複用途選單、重複總數及停用分頁排在圖片之前；方形連結框留下黑色空白 | 用途左側、搜尋右側，同列排列；三欄 4:3 圖片；編輯／封存及前處理版本仍在素材管理內，完整流程能力與分頁仍可使用。 |
| 模型庫 | 來源、搜尋、顯示切換分成多排，清單起點太低 | 分類與清單／卡片同列；預設清單，卡片為三欄；尺寸示例、可使用狀態及套用按鈕對齊。搜尋、來源、授權、編輯、偏好與驗證紀錄保留於具名展開區。 |
| 實驗比較 | 預設是大型參數表單，結果不在主要位置 | 先顯示目前方案、固定條件及三欄比較；建立方案時才展開表單。既有方案可直接選取；結果、評分入口、任務／完整紀錄與 JSON 保存匯入均保留。沒有方案時顯示真實空狀態。 |
| 訓練審查 | 匯入表單搶占主畫面；縮圖、原圖與欄位沒有照預覽分欄 | 四階段與簡短說明、審查進度、待補訊息，以及縮圖／原圖／主要欄位三欄。保留待補篩選及標記；完整缺項、角色／來源欄位、版本與匯出均可展開。「保存並看下一張」只在保存成功後切換。 |
| 設定 | 分類與表單上緣差 6px，連線狀態呈現不一致 | 對齊分類／表單起點；維持測試不保存、保存並套用的區分，狀態集中呈現。 |
| 系統資訊 | 基本結構已對齊，數據與原型示例不同 | 保留統一寬度、摘要與四分頁。實際 GPU、RAM、磁碟、引擎未知值與失敗狀態如實呈現，不代入原型的假資料。 |
| 局部修補 | 筆刷工具順序與參考不同，羽化只在進階數字欄 | 主要列依筆刷、擦除、大小、羽化、反相、清除排列；額外復原／重做保留。原尺寸二值 PNG、鍵盤區塊與保存行為未刪除。輸出與原圖不同時清楚分別顯示，不再誤寫「沿用原圖」。 |

以 1440×900 為例，素材第一排由約 y=523 回到 y=219、模型清單由約 y=567 回到 y=213，作品清單由約 y=359 回到 y=259。這些量測來自相同視窗下的實際瀏覽器，不以更改原型來縮小差異。

## 一併發現並修正的功能問題

- 版本 1 比較方案的 hash 會區分 `7.0` 與 `7`。瀏覽器重新編碼可能破壞文件，導致保存失敗。保存／匯出現在保留原始文件文字，重載透過只讀 `/api/experiments/plans/{id}/document` 取回；既有 hash、版本與原請求契約不變。
- 從創作返回比較頁時，重新讀取已保存的結果；不聯絡引擎，也不提交新任務。卡片只顯示最近一次任務的圖片，舊結果留在歷史中。
- 模型架構選單原先可能被 FLUX 工具列蓋住，已修正層級並在選擇後收合。
- 訓練縮圖欄的完整篩選改為直列，避免欄位被擠成不可操作；大量縮圖在欄內捲動，未保存標註、缺項定位及最終評估圖片保護保留。

## 驗證

- `npm.cmd run build -- --configLoader runner`、`format:check`、`lint` 與 `npm.cmd test` 通過。
- 新增直接開啟 `preview.html` 的 Playwright 對照：1280×800、1440×900、1920×1080，驗證內容／工具列／清單起點、搜尋位置、欄寬、畫布、比例按鈕及清單／卡片預設。主要定位的容差為 2–3px；不是整頁逐像素相同的宣告。
- 28 個受影響瀏覽器案例已分批通過：原有桌面與狀態保留 12 項、遮罩 6 項、125 張訓練導覽 2 項，以及新增對照／比較原始文件／實際結果／保存失敗保留／瀑布流比例 8 項。修正後僅重跑受影響的項目，沒有宣稱完整舊版瀏覽器套件全部通過。
- 比較方案相關後端 33 項通過，涵蓋新文件讀取、不寫入、不連引擎、hash 與精確 Seed。
- 所有生成／訓練相關驗證均使用拋棄式資料和模擬引擎；未操作正式作品或啟動真實 GPU 任務。保留既有手機／模擬觸控遮罩回歸，不代表新增手機版需求或手機驗收。
- Vite 仍提示主 JS 超過 500 kB；本次未拆分載入。

## 資料與仍未實作的能力

原型的山巒、模型名稱、數量、820／96／564 GB 等是示例，不應出現在沒有對應資料的正式平台。既有規劃中的分類容量掃描與全域任務抽屜仍依 [整合紀錄](IMPLEMENTATION.md) 的後續範圍處理。批次作品操作已於後續修正實作，見下段。

### 作品選取的後續修正

正式版先前選圖就立即展開比較區，未依原型先顯示選取操作列。現在先出現「已選 N 件／並排比較（2–4 張）／批次封存／批次下載原圖／清除選取」，按比較後才切換到獨立作品比較畫面；返回保留選取、篩選及分頁。已封存篩選下顯示「批次還原」。原圖 ZIP、逐件修訂衝突、部分失敗、停止後續保存及明確重讀狀態均已接入；詳見 [整合紀錄](IMPLEMENTATION.md#作品選取與比較流程修正)。

後端新增只讀文件與原圖打包端點，更新執行中的平台時需重啟後端；前端也須載入本次重新建置的資產。截圖來自隔離測試平台，不是使用者正式資料。本次作品流程的 15 個針對性瀏覽器案例與 10 個後端測試分批通過，詳見整合紀錄。
