# 系統資訊：目錄與磁碟容量

容量摘要顯示可用空間、總容量與可讀磁碟區數，各磁碟卡顯示使用比例及所屬目錄。同一實體磁碟區只計算一次，容量是磁碟區整體容量，不是遞迴計算的資料夾大小。更新失敗保留上次快照並標示失敗；未取得的容量顯示未知，不當成零。

每個目錄右側的資料夾圖示可在 Windows 檔案總管開啟其位置，支援鍵盤及至少 44px 點擊範圍。此操作開啟平台主機的本機目錄；請從該主機的 `127.0.0.1` 或 `localhost` 平台頁面使用。未建立、不可讀的目錄及非 Windows 平台停用按鈕；目錄不會因點擊而建立，也不會改開父目錄。磁碟容量未知但目錄仍可讀時，開啟功能仍可使用。

更新程式後需重新啟動平台，再重新整理頁面。若原本的舊版平台仍在執行，新介面會保留目錄顯示並提示重新啟動，避免把尚未載入的功能誤判為主機不支援。

`GET /api/storage` 沿用唯讀目錄／磁碟快照，另提供固定目錄 ID、Windows 開啟能力及逐目錄 `can_open`。額外 checkpoint 的 ID 由保存的完整路徑雜湊建立，排序變更不會把舊按鈕指向另一個目錄。

`POST /api/storage/open-directory` 僅接受 JSON 的 `directory_id` 與快照 `expected_path`。後端重新從固定及已登記的目錄清單查找目標，驗證為既有可讀的本機目錄，再比較實際位置；不接受任意檔案或路徑作為開啟目標。路徑已移除或變更需先更新快照。僅接受本機連線、loopback Host 及相同來源的請求，拒絕網路／UNC 位置。最後透過 Windows `os.startfile` 開啟目錄，不組合 shell 命令。

按鈕等待期間停用重複操作；開啟失敗顯示訊息，不自動重試。成功訊息代表檔案總管已接受開啟要求，不能確認使用者是否已看見視窗。操作不讀取模型內容、不提交生成、不修改平台資料庫。

驗證：31 項目錄、模型路徑及 Windows 別名相關後端測試；桌面／390px 的容量、長路徑、鍵盤／點擊、遺失目錄、失敗不重試及舊快照保留回歸。原有系統資訊的無障礙掃描另涵蓋本區。

2026-10-24 在 runtime 隔離資料的真實平台，由瀏覽器點擊「平台資料」圖示，Windows 接受檔案總管開啟要求且介面顯示成功訊息；未使用正式作品資料，也未提交生成。介面截圖使用固定容量與路徑的測試資料，容量數字僅為版面展示。
