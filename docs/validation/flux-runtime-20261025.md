時間含載入、編碼、取樣、解碼及觀察成本，不是純 GPU 時間。每次是新程序，檔案快取未知，驗檔先前已完整讀取權重。第二次曾與一輪品質檢查重疊，模擬派送被租約正確阻擋；該輪測試失敗保留，之後在 worker 退出／租約釋放後獨立重驗。這兩次不是乾淨的效能比較，也不能把整卡／主機共用數字當成任務專用需求。

## 真正觀察到的精度與卸載

- 主模型檔案有 776 個 BF16 tensor；載入後主要權重為 FP8。第一次取樣後邏輯參數約 10.170 GB 在 CUDA、1.721 GB 在 CPU，另有少量 FP32；觀察到 352 次 CPU FP8 權重轉到 CUDA BF16，以及 1,504 次 CUDA FP8 轉 BF16 的呼叫。這些是實際張量觀察，並非只記錄選項。
- CLIP-L 檔案 196 個 FP16 tensor，載入主要為 CPU FP16；觀察到 CPU FP32 輸入與回傳權重。T5 檔案混合 169 個 FP8、52 個 FP16、168 個 FP32 tensor，載入後主要為 CPU FP16，觀察到 CPU FP32 cast；本配置並非 T5 全程以 FP8 計算。
- VAE 檔案 244 個 FP32 tensor；實際載入後 BF16 參數在 CPU，解碼後在 CUDA。沒有觀察到的 kernel／累加器精度仍未知，邏輯 tensor bytes 不是精確 VRAM 配置量。

## 3060／4080 提醒

這台 64 GiB RAM 的 RTX 3060 可以完成所列小型配置，尚無理由要求為此案例改用 4080。但模型載入期間程序 RSS 超過 36 GiB，主機記憶體接近用滿；**不能承諾 32 GiB RAM 或更大尺寸**，也不能把 12 GiB VRAM 當成官方最低需求。部署另一台機器仍須核對實際 VRAM／RAM、驅動及相同條件；需要不同精度／卸載或 4080 時，先按 [提醒規則](../models/flux-rtx3060-planning.md)說明，再測。

## 程式驗證與後續

最終獨立品質檢查 770 項後端通過（1 項既有跳過）、型別／build／四組契約通過，全部 Chromium 120 項分四批通過。合成回歸另驗證混合檔案精度不冒充執行精度、標頭大小／offset 拒絕、觀察有界、預設不啟動 GPU、引擎狀態未知拒絕、逾時只停止自己的 worker 並保留失敗回執。實際 GPU 證據與合成測試分開。
